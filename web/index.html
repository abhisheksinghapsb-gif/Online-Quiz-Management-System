Answer: We created the abstract class Question because all questions share state (id, questionText, marks, topic, difficulty) and helper logic (displayHeader()), but a generic question cannot be answered directly. By declaring displayQuestion() and checkAnswer() as abstract, we enforce subclass implementation in MultipleChoiceQuestion, TrueFalseQuestion, and NumericQuestion while preventing illegal instantiation of a naked question.

Answer: Polymorphism is used in both forms:
Runtime (Method Overriding): When iterating over List<Question>, calling q.displayQuestion() and q.checkAnswer(ans) uses dynamic method dispatch. Also, QuizEvaluator swaps between StandardGradingPolicy and NegativeMarkingGradingPolicy at runtime.
Compile-Time (Method Overloading): QuizOperations.searchQuiz(String topic) vs searchQuiz(String topic, DifficultyLevel level), and overloaded InputValidator.readInteger(...) methods.

Answer: An abstract class (Question, User) represents an IS-A relationship with instance variables, access modifiers, and constructors. An interface (QuizOperations, QuizEvaluator) represents a CAN-DO behavioral contract without instance state, supporting multiple implementations and loose coupling.

Answer: To implement the Strategy Design Pattern. Different exams require different grading rules: standard linear grading for internal tests vs negative marking for competitive exams. Abstracting this behind QuizEvaluator allows us to add new grading policies without modifying existing quiz conduction code (Open/Closed Principle).

Answer: We built a custom checked exception hierarchy rooted at QuizException:
• QuizNotFoundException: non-existent quiz ID.
• DuplicateQuizException: duplicate ID during quiz creation.
• InvalidOptionException: illegal student choice (e.g. entering 'Z' on MCQ).
• InvalidQuestionException: negative marks or invalid options count.
• EmptyQuizException: taking a quiz with zero questions.
All are intercepted with targeted try-catch blocks to prevent application crashes and guide the user.

Answer: try isolates code that may produce exceptional states; catch intercepts and recovers from specific domain exceptions; finally guarantees unconditional execution for cleanup, closing resources, and logging audit confirmations.

Answer: Group roles are divided into: (1) Architecture & Abstract Base Classes, (2) Specialized Concrete Models, (3) Interfaces & Grading Policies, (4) Custom Exception Hierarchy & Input Validation, and (5) UI & Automated Test Suite.

Answer: Because of loose coupling:
• Adding a new question type: create a subclass of Question (existing code untouched).
• Adding a new grading rule: create a class implementing QuizEvaluator.
• Switching to a Database: create DatabaseQuizManager implements QuizOperations.
